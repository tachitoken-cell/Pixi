# MOSS ingame store

The store uses its own `MossvaleStore` contract on Robinhood Chain mainnet (4663), separate from auctions. Each exclusive mount costs $40 of MOSS, each pet $20, and the **Burned** title $100. Unlocks belong to the purchasing character. Mounts keep the existing level 25/riding requirement and speeds; pets are cosmetic. Store rewards are unavailable through gold vendors, loot tables or the auction house.

The character links a wallet by a single-use ownership signature, requests a USD quote, reviews the exact MOSS amount, then explicitly approves and burns. The approval is for the exact amount. `buy` calls the existing MOSS token's native `burnFrom`, checks both the buyer balance and total supply decrease by precisely that amount, and records `paidOrders[orderId]`. No MOSS goes to the game operator or remains in the store contract. ETH pays network gas.

EIP-712 orders bind the store contract, chain, unique order, character, product, verified wallet, token amount, USD price and five-minute deadline. Altered orders, other buyers, replay, expired orders, and ETH transfers revert. The realm saves the signed order before sending it to the browser. A matching `paidOrders` entry in a fresh canonical `latest` block completes the reward after exact order validation. Here **processed** means successful inclusion and contract state; a mempool transaction, submitted hash, or approval alone grants nothing. The contract writes payment only after the exact burn succeeds. Success returns the existing `paid` settlement result, regardless of whether the finalized head has reached the payment.

The realm saves completed rewards atomically, including offline characters. Already delivered rewards remain permanent after a later chain reversal: this is an explicit acceptance of sequencer settlement risk. Legacy saved provisional orders retain their anchor validation and advance to completed delivery when the current payment is verified. RPC outages, missing historical blocks and regressed or stale current heads fail closed before delivery. A current successful payment does not require the finalized head timestamp to be less than thirty minutes old; negative unpaid-expiry decisions still do.

Closing the browser before reporting a transaction hash does not lose the purchase: contract storage independently recovers it. Failed saves retry. Finalized unpaid expiry permits a new quote; wall time alone never does. An unresolved purchase blocks character deletion and wallet replacement. Delivered orders remain with the character for restart-safe idempotency. Robinhood describes sequencer execution as a reversible soft confirmation, with stronger assurance after Ethereum posting and finality; `latest` and `finalized` are the EVM RPC block tags used here, while **processed** describes the successful inclusion accepted for game delivery. See [Robinhood transaction finality](https://docs.robinhood.com/chain/transaction-finality/) and [Ethereum JSON-RPC block parameters](https://ethereum.org/developers/docs/apis/json-rpc/).

## Boosts and cosmetic boxes

The catalog in `src/ingame-store.ts` adds four $2 boosts: +50% character XP, +50% gathering/crafting XP, +20% damage, and +20% defense. Each verified processed purchase grants one charge. Activate it from **Store → Boosts** for one hour; another charge adds one hour without stacking power. Active timers persist across reconnects and continue while offline. Damage includes spells, auto attacks and poison; defense increases the armor stat used against monsters, players and dungeon hazards. Character XP covers ordinary rewards; GM level grants are unchanged.

The $5 **Cinder Cosmetic Box** unlocks one unowned store mount or pet. Each remaining cosmetic has equal odds, shown before purchase. The four-reward pool has no duplicates and closes when complete. A box and another cosmetic purchase cannot be pending together. Boosts and boxes deliver after successful processing; their immutable receipts and rewards are saved together, so retries cannot duplicate charges or reroll a delivered box. A later chain reversal does not undo a delivered reward. An offline purchase delivers a boost charge without starting its timer. These are USD-denominated MOSS burns; no card checkout is configured.

The original immutable contract accepts only the $20/$40/$100 tiers. The $2 boosts and $5 box require deploying the rebuilt contract, which also retains all original tiers. Upgrade both realms before enabling the new catalog: old runtimes do not recognize new product receipts, boost fields or rolled gear IDs. Rollback must keep support for those saved values.

## Deployment

1. Run `npm run build:store-contract` and `npm run check:store`.
2. Use a signing authority stored only in server secrets as `STORE_AUTHORITY_KEY`. The existing `MOSS_AUCTION_AUTHORITY_KEY`, then `AUCTION_AUTHORITY_KEY`, is the fallback. This key signs orders and needs no funds. Never put it into browser code or commit it.
3. Open `/store-deploy.html`, enter only the authority's public address, connect a funded wallet, and review the separate contract deployment in that wallet. The constructor pins the chain and existing MOSS token. This setup page creates no token and does not burn funds.
4. Set `STORE_CONTRACT` to the new contract address in **both realms**. When replacing the original contract, also set `STORE_LEGACY_CONTRACT` to the previous address in both realms, keeping the same signing authority. The US Compose file forwards this setting. Set `STORE_RPC_URL` to an archive RPC supporting finalized historical state; the default is `https://robinhood-mainnet-rpc.blockreq.com/v1/rpc/public` (or `MOSS_AUCTION_RPC_URL` if present).
5. Restart the realms and open the store. It stays disabled until the server verifies the finalized runtime hash, token runtime/metadata, signing authority, and fresh price data. Missing setup or unavailable pricing never substitutes a fixed price or a direct transfer.

For the processed-reward update, stop both old realm runtimes before starting either new runtime: old versions reject provisional saved orders. Once provisional orders exist, rollback must retain support for that saved state. Run `npm run check:store-realms` for the disposable PostgreSQL/two-realm reconciliation check.

New quotes always use `STORE_CONTRACT`. Pending and provisional orders retain their signed contract address: settlement and receipt verification route to `STORE_LEGACY_CONTRACT` only for that exact address and the pinned original runtime hash. The legacy route cannot create quotes. Keep the legacy configuration until every old purchase is delivered or expired; RPC errors preserve existing provisional rewards. Do not rotate the signing authority while any purchase is pending, and do not replace a second time while the first legacy contract still has unresolved orders. Preserve both addresses and the signing authority in rollback configuration. The build and local checks do not deploy a contract, alter a live realm, or burn mainnet MOSS.

## Dollar quotes

The server reads the pinned graduated MOSS/RBLX Uniswap V4 pool at three finalized blocks spanning approximately five minutes. It uses the lowest sampled MOSS/RBLX price and Robinhood's fresh RBLX/USD bid, including the current shares-per-token multiplier. It rounds the burn amount up to the nearest MOSS base unit. The player sees the exact amount and quote expiry before wallet confirmation.

Pricing fails closed for stale/missing issuer quotes, halted assets, wrong token/chain metadata, excessive bid/ask spread, unavailable finalized history, or less than $10,000 **virtual** quote liquidity. Price movement between samples does not block quotes. Virtual liquidity is not executable market depth. Three discrete samples are a conservative market estimate, not an exact TWAP or a manipulation-resistant oracle; use an independent MOSS oracle before relying on this mechanism for higher-value or redeemable rewards. There is no manual dollar-price override.

Primary references: [Robinhood stock token APIs](https://docs.robinhood.com/chain/stock-token-apis/), [RBLX issuer quote](https://api.robinhood.com/rhj/prices/RBLX), [Uniswap V4 StateLibrary](https://github.com/Uniswap/v4-core/blob/main/src/libraries/StateLibrary.sol), [Pons token source](https://github.com/ponsdotdev/ponsfamily/blob/main/contractsV2/src/v2/PonsV2LauncherToken.sol).

## Checks and art

`npm run check:store` runs the actual reviewed MOSS bytecode and new store bytecode in a local EVM, processed/finalized recovery, reorg/re-inclusion and stale RPC guards, adversarial quote/receipt checks, the real game WebSocket/persistence flow, and browser-side payment validation. `node scripts/check-store-chain.mjs --live` additionally verifies current read-only pool and issuer pricing. No check broadcasts a transaction.

`scripts/build-store-assets.py` creates the four articulated Blender models and five store icons. Source: `assets/source/store-collection.blend`; runtime: `public/models/store-collection.glb`; render gallery: `assets/source/store-collection-preview.png`. Existing mount, pet, trainer and loot checks cover exclusive acquisition and shared animations.
